# DaWiz

NHL pool standings page. See README.md for the overview and file layout.

## Rules to keep

- Scoring: 1 NHL point = 1 pool point. Skaters only. Bench players are shown but never count toward totals, GP, PPG or the "tonight" count.
- Game pill: a player whose team has a game today gets a grey pill on the name line, always with minutes ("7:00 PM vs OTT", "7:30 PM @ MIN"), text slightly smaller than the player name. It is grey on purpose: green is reserved for points scored (the Last Night pill). It shows every game today whether or not it has been played; there are no live/final variants. The time is rendered in the viewer's time zone in the browser (`gamePill` in `common.js`); `standings.mjs` supplies opponent, home/away and UTC start from the NHL schedule and ignores postponed games. "Playing Tonight" counts every player with a game today.
- Ordering: active players are in feed order (draft round 1..16) and bench is in feed order (B1..B8). Do not sort players by points. Only the owners in the standings sort, by rule 9 of the pool's rules: TP, then PPG (exact, not the rounded display), then goals, then fewest GP (`byStandings` in `standings.mjs`, also used for The Money's places).
- Positions and prices: `data/bibleFeed.csv` is the source of truth for player positions and draft prices. Never display the NHL API's position. A bible price of $0.00 on a drafted player is a "freebie": price = (owners x 16 + 1 - draft pick) / 100, computed in `build-rosters.mjs` (the bible stays untouched). Prices are shown for active players on Standings and on the Draft page. Bench prices are deliberately not displayed (they don't matter); bench rows show "Times Picked: N" instead (how many owners have that player on their bench, computed in `standings.mjs`). Overnight has no prices. `scripts/build-bible.mjs` turns it into `netlify/lib/bible.json`, which `build-rosters.mjs` and the Overnight function read (NHL position is only a fallback for a player missing from the bible).
- Round money (RM): in each draft round, active players with at least 1 point are ranked by TP and places 1-4 pay $3.00 / $2.26 / $1.50 / $0.74; tied players split the pool of the places they cover, rounded to the cent. Computed live in `standings.mjs` (`roundMoney`), shown per player in rosters (phones too) and as an owner total (Standings column on desktop, roster Total row everywhere). The pool's old Google Sheet had a one-owner column shift in RM; the live computation replaces it, so don't copy RM from the sheet. RM sits right after PPG, both in the owners table (hidden on phones) and in rosters.
- CSV IDs drop the leading `84` (sheet `78402` = NHL API `8478402`). `scripts/build-rosters.mjs` adds it back.
- All NHL API calls go through the Netlify functions (`netlify/functions/`), using shared helpers in `netlify/lib/nhl.mjs`. Browsers can't call that API directly. The one non-NHL source is ESPN's public NHL injuries feed (the NHL API has no injury list), also called only from a function (`injuries.mjs`).
- Overnight page: lists everyone with at least one point on the previous ET day, plus every active-roster player who played without scoring (so owners' players who played all show). An owner chip means an active roster spot. Wide screens add season GP/G/A/TP/PPG columns. Bench players are deliberately ignored on this page (a bench-only scorer shows as unowned). Owned players' points must add up to the Standings "last night" TP column, and their count to its GP column.
- Draft page: `public/draft.json` is a frozen snapshot of the original draft (snake order; owner order in `rosters.json` = round-1 pick order). Do NOT regenerate it after the midseason drop/pick, because the CSV's round rows will then hold replacement players. `scripts/build-draft.mjs` refuses to overwrite without `--force`.
- Draft page "current" section: GP, TP and RM for each pick, from `/api/standings` matched by player id on the owners' active rosters (no extra function). Wide: three columns right of Owner, after a divider, so the draft columns stay on the left. Phones: a line under the name. A pick no longer on an active roster (after the drop/pick) shows blank. The draft renders first and the numbers fill in when standings arrive. The Round and Owner menus are either/or: choosing one resets the other. Below 1160px the two menus drop to their own row (they didn't fit the top row with six tabs; not re-checked since Draft left the tab bar).

## Workflow gotchas

- After any change to `data/bibleFeed.csv`, run `node scripts/build-bible.mjs` then `node scripts/build-rosters.mjs`. After any change to `data/teamFeed.csv`, run `node scripts/build-rosters.mjs` and commit the generated JSON (`bible.json`, `rosters.json`) with it. Netlify does not run the script.
- The local server (`node server.mjs`) caches the function and `rosters.json`: restart it after changing either. Edits under `public/` only need a refresh.
- The NHL API rate-limits bursts. Don't fire many parallel requests; the build script retries with backoff for this reason.
- Do not push, deploy or change the live site without asking first. The repo is public.
- Netlify auto-publish is OFF. Pushing to GitHub does not change the live site; the owner publishes from the Deploys tab. Each production deploy costs 15 of 300 free monthly credits, so batch changes. Commits and pushes are free.

## Decisions already made (don't re-propose)

- Standings stay live (they include today's finished games). Freezing them at the end of the previous day, rolling over at ~6 AM ET, was discussed and declined.
- Making the TP column visually prominent (bigger, framed, accent-colored header) was tried and rejected; TP keeps the normal stat styling.
- The "Powered by Netlify" badge is not removable from code; hiding it with CSS was declined as working around Netlify's branding.
- The `Times Picked: N` label (capital P, with colon) and the `Last Night:` label (capital N, with colon) wording is as requested.
- Bench prices are not shown; bench scorers are ignored on Overnight.

## Style

- Keep it plain: static HTML pages (`index.html`, `overnight.html`, `draft.html`, `team.html`) sharing `style.css` and `common.js` (which also renders the tab bar and More menu: add new pages to `TABS` there, with where they show and their More group). No framework, no build step.
- UI is deliberately large with generous spacing for readability. Don't shrink text or tap targets without asking.
- Wide screens (min-width: 1000px) get the data-rich tables of the old site: open rosters split Rd/Pos/Team/Cost into their own columns (`.wd` cells), and Overnight adds season columns (with Pos and Team columns, like Draft; no "Season" label over them). Phones and tablets keep the compact layout. The bench label row exists in a narrow (`nw`, colspan 8) and wide (`wd`) version because CSS can't change colspan.
- Large-screen sizing (min-width: 1000px): 80% text size (`html { font-size: 15px }` vs 19px), as requested; phones and tablets keep the large sizes. Owner-row padding and page spacing are tightened so the whole Standings page (all 12 owners, rosters closed) fits in ~700px of height without scrolling; re-check that after adding anything above or in the owners table (or to the pinned top band). The page title sits on the tab row (title, tabs, date/filter, theme toggle), done in CSS by making `main` a grid and the `header` `display: contents`; every page keeps the same `nav` + `header` markup for this to work. `common.js` wraps `nav` + `header` in a `.topbar` div (no per-page markup), which is the grid on wide screens and is pinned to the top of the window (`position: sticky`, full-width background via a box-shadow spread on `::before`, so it adds no sideways scroll and doesn't clip the More dropdown). Its height goes in `--bar-h` (ResizeObserver), and every table's column-header row sticks just under it: `thead` (the whole block, so Standings' two header rows stay stacked), `.scorer.head`, `.ud.head`, `.bp.head` and Draft's `.roundhead`. Cards use `overflow: clip`, not `hidden`, on wide screens (hidden would stop sticky). Wide screens only, as agreed with the owner: on phones the band would eat too much of the screen, and flicking back to the top is easy there.
- Benches tab (`benches.html`): pivots every owner's bench from `/api/standings` into one row per player (sorted by TP, owner columns alphabetical). Wide (1000px and up): check-mark grid, one column per owner, like the old site's Benches page. From 1000 to 1149px the owner columns are narrower and the owner names in the header read upright (bottom to top), with a smaller photo and logo; 1150px and up keeps level names. (The grid used to start at 1150px, so a ~1070px laptop got the phone chips, which the owner reported as broken.) Phones and tablets: owner chips.
- Undrafted tab (`undrafted.html`, `/api/undrafted`): top 200 scorers (>= 1 point) not on an owner's ACTIVE roster (drafted = active spot; bench does not count). Bench owners show as the same solid owner chips as the Benches page (a "Bench:" label on phones, an "On bench" column on wide screens). For the drop/pick, bible price over $2.50 (`MAX_COST` in the function) means ineligible: row dimmed, red price, red "Ineligible" pill under the name (not beside the price, which keeps the Cost column aligned), banner on top, "Eligible players only" checkbox. Players dropped in the midseason drop/pick would show up here, since drafted means on a current `rosters.json` active roster.
- Menu: only the daily pages are tabs on phones (Standings, Overnight, then a More button), so the bar fits one row at 360px with no sideways scrolling. Wide screens add Teams as a tab. Everything else is in More, under group headings (Draft: Draft, Undrafted, Benches; Charts: The Chase, Who's Hot; Pool: The Money; NHL: NHL Teams); Draft was moved off the wide tab bar into More, as requested. The groups are an accordion: each is a `<details>` sharing one `name`, so only one is open at a time, and the group holding the current page starts open. The panel is styled to stand out from the page (a lifted surface a touch lighter than the cards, an accent-tinted edge, a deep shadow), headings are shaded bands (the open one in the accent colour) and destinations are indented under a thin accent guide line, as requested so topics and destinations read differently. Hover-to-open was discussed and not done (the list jumps under the mouse as groups open and close; phones have no hover). More is a `<details>` (opens without script), a full-width panel on phones and a dropdown under the button on wide screens; it is highlighted when the current page is inside it. Agreed with the owner because more pages are coming; the old site's 7 squeezed top items plus an "Other Stuff" list were the model to avoid.
- The Chase (`chase.html`, a Charts page in More): per owner, points per game so far and the pace needed over their remaining roster games to finish level with the leader, if the leader keeps their pace. A dot for each on a shared scale, a dashed line at the leader's pace. Games left = each active player's team's games left in the season (`SEASON_GAMES` in `standings.mjs`: 84 games from 2026-27, 1344 league games; `left` in `/api/standings`, from the NHL standings endpoint; an upper bound, ignoring injuries). Drawn as HTML rows, not an SVG, so text keeps its size on phones (the scale header is hidden there; the numbers are in each row's text line). Early in the season every owner needs only a little more than the leader's pace; the gaps open up late in the season, which is the point of the chart.
- Who's Hot (`hot.html`, `/api/hot` in `netlify/functions/hot.mjs`, a Charts page in More): points each owner's active players scored over the last 14 complete ET days (two aggregate NHL stats calls: the window and the season), sorted by those points. A bar per owner and an upright marker at "usual" = season points per game x games played in the window, so playing more games doesn't count as hot. The marker uses the text color so it shows in both themes (a black marker vanished in dark). Same row layout as The Chase, with a short plain-language explanation under the chart.
- The Money (`money.html`, `/api/money` in `netlify/functions/money.mjs`, More under Pool): the pool's money sheet. Entry $40 per owner; pots Half-Way Point $40 ($25/$15), Regular Season $200 ($100/$60/$30/$10), Round Money $120 (the live `roundMoney`, same as Standings), Playoff Money $120 ($60/$42/$18: a separate playoff pool, to be built later; always blank for now). Places are by owner TP (active players only). Half-Way = the standings at the end of the day the league's games played reach half the season's total (`HALFWAY`, 2027-01-03 for 2026-27: 672 of 1344; re-check each season), computed from a game-date stats call. Until a date passes, its pot is provisional ("if it ended today", italic); Regular Season is final once every team has played `SEASON_GAMES`. Rows rank by Total. Take-Home = Total - $40, losses in red brackets. Wide: one column per pot; phones: Owner, Total, Take-Home with the pots on a line under the name. Half-Way and Regular Season places follow the DaWiz standings order (rule 9 on the Rules page: TP, then PPG, then goals, then fewest GP; `byStandings` / `standingsKey` in `standings.mjs`), as confirmed by the owner; only owners equal on all four would split places. Before the drop/pick changes `rosters.json`, freeze the Half-Way winners in `HALFWAY_PAID`. The pool's sheet is not a source for these numbers (it's often out of date).
- Injury (`injury.html`, `/api/injuries` in `netlify/functions/injuries.mjs`, More under Draft, menu label "Injury" as requested): every pool player, active or bench, on the NHL injury list, from ESPN's unofficial public feed (`site.api.espn.com/.../nhl/injuries`, no key). ESPN has its own player ids, so players are matched by name (accents and punctuation ignored) plus NHL team (ESPN codes LA/NJ/SJ/TB mapped to LAK/NJD/SJS/TBL), so a same-named player on another team doesn't match. Sorted most serious first (IR-LT, IR, IR-NR, Out, Day-to-day), then by ESPN's estimated return. Shows status pill (red when out of the lineup, grey for day-to-day), injury type, estimated return ("Any day" when it's today or past), ESPN's one-line note, and owners (solid chip = active spot, outlined = bench, like the NHL team page). Owner filter like Benches. Wide: one column each; phones: lines under the name. Roster rows (Teams, NHL team page, Standings rosters on phones) also get an injury pill on the name line after the game pill, e.g. "Out · Back Nov 18" (red) or "Day-to-day · Back any day" (grey), with ESPN's injury type and note as the tooltip: `injuryPill` / `loadInjuries` in `common.js`. The report is fetched at most once per page and never holds up the roster: Teams and the NHL team page start it at load and redraw when it arrives; Standings fetches it only when a roster is first opened (so a normal Standings visit makes no extra function call). If ESPN changes or drops the feed, the Injury page and these pills are what break.
- Rules (`rules.html`, More under Pool): the pool's rules, ported from the old site (Other Stuff > DaWiz Rules) as static HTML, one card per rule; edit the text in the page. Small fixes made in porting: rule 2's "See 10" points to rule 9 (standings criteria), "found 4" -> "rounds 4", "form the pool" -> "from the pool". Rule 9 (TP, then PPG, then goals, then fewest GP) is applied to the Standings order and The Money's places.
- Footer on every page, added by `common.js` (no per-page markup): the owner-supplied cartoon of a player in an orange old-school helmet (`public/goring.png`: white background made transparent so it sits on either theme, cropped, 159x180 so it stays sharp at 53x60 on high-density phones, 64 colours, ~7 KB) and a tongue-in-cheek credit to "the DaWiz IT professionals", as requested. On wide screens it is tight enough that Standings still fits in ~700px. `server.mjs` serves `.png` as `image/png` for it.
- NHL team page (`nhl.html?team=EDM`, "NHL Teams" in More, under NHL): every NHL team logo on the site is clickable and opens it. One blended list of every current skater on that team, best scorers first, in the Teams page's table (`rosterTable(o, true)`) with an Owner column in place of Team: a solid owner chip = an active roster spot (round and RM shown); outlined chips = owners who have the player on their bench ("Times Picked: N" on phones); no chip = unowned. Owned players come from `/api/standings`, the rest of the roster from `/api/nhlteam?team=EDM` (`netlify/functions/nhlteam.mjs`: roster, season totals, last night, today's schedule, bible position and price; goalies left out). As requested, owned and unowned players are not split into sections. Total row of everyone listed. A team select lists all 32 teams (results cached per visit); the `team` URL value must be a 3-letter code (it goes into the page). Logos often sit inside a player's link (to NHL.com) and links can't nest, so `logo()` puts `data-team` on the image and one capture-phase click handler in `common.js` navigates (and stops the player link and the Standings row toggle). `server.mjs` passes the request to functions (like Netlify) so they can read the query string.
- Teams tab (`team.html?owner=Name`): one owner's full roster table, wide screens only (the tab is hidden below 1000px; phones expand a team in place on Standings). On wide screens, clicking an owner on Standings opens their Teams page instead of expanding. The roster table markup is shared: `rosterTable(o)` in `common.js`, used by both pages.
- Owners' rosters show the team as a large logo only, no abbreviation (`logo(team, true)`; the abbreviation appears only if the logo fails to load). On wide screens Overnight and Draft match (Pos and Team in their own columns, big logo; Overnight adds the opponent under the logo, e.g. "vs STL"; the round label on Draft doubles as the column header row). On phones and tablets Overnight and Draft keep the small logo + abbreviation line under the name.
- It must fit phone widths (360px and up) with no sideways scrolling; the Standings table is tuned to still fit down to 320px (see the `max-width: 350px` rule in `style.css`). On phones the PPG column is hidden to make room, and open rosters show each player's GP/G/A/TP/PPG (PPG = TP / GP, 2 decimals) on one line under the name; PPG wraps to a second line only when the row is too narrow, and the Last Night badge always gets its own line.
- Standings group headers ("Season", "Last night") use colspan, and CSS can't change colspan. When a column is hidden on phones (PPG), keep a separate phone version of the header (`th.s5` desktop / `th.s4` phone) or the headers drift out of line with their columns. Re-check header alignment whenever a column is added, removed or hidden.
- On phones no text may be smaller than ~14px (older users struggled with small text). Don't shrink fonts to make something fit; change the layout or hide a lower-value column instead.
- No auto-refresh of any kind (timers or refresh-on-focus burn free-tier credits). Each page fetches its data once on load; visitors reload to get new data.
- Light and dark themes: the device setting (`prefers-color-scheme`) by default, overridden by the header toggle (☾/☀︎, saved in `localStorage.theme`, applied as `html[data-theme]` by a one-line script in each page's `<head>` so there's no flash). The dark palette is defined twice in `style.css` (media query + `[data-theme="dark"]`): change both together. NHL logos have light/dark versions; `logoSrc` in `common.js` picks one and the toggle swaps them. Don't use CSS `light-dark()` (too new for older iPhones).
